# Mosquitto MQTT Broker Test Setup

This directory contains a container setup for running a local
Mosquitto MQTT broker with TLS support, used for testing the
STM32F405 TLS handshake and MQTT client implementation.

## Prerequisites

- **Container runtime** — one of:
  - [Podman](https://podman.io/getting-started/installation)
    (preferred)
  - [Docker](https://docs.docker.com/get-docker/)
- **OpenSSL** — for TLS certificate generation
- **mise** — task runner
  ([install](https://mise.jdx.dev/getting-started.html))

### macOS Additional Prerequisites

You need a container VM backend appropriate to your runtime:

**Podman users:**
- **Podman Machine** (built-in): `podman machine init && podman machine start`
- **Lima** (alternative): `brew install lima && limactl start podman`

**Docker users:**
- **Docker Desktop**: install from [docker.com](https://www.docker.com/products/docker-desktop/)
- **Colima** (alternative): `brew install colima && colima start`

## Quick Start

```bash
# From the repository root (recommended — auto-generates certs):
mise run broker:start

# Or directly (requires certs to already exist in .local/):
test/broker/start-broker.sh
```

> **Note:** `mise run broker:start` automatically generates TLS
> certificates via its `tls:server:broker` dependency.  Running
> `start-broker.sh` directly assumes certs are already present
> in `.local/certs/` and `.local/private/`.  Generate them first
> with `mise run tls:server:broker` if needed.

The script auto-detects the container runtime and platform:

- Prefers `podman` if available, falls back to `docker`
- Set `CONTAINER_RUNTIME=docker` (or `podman`) to override
- **Linux:** binds to interface `eno1` at the detected IP
- **macOS:** binds to `127.0.0.1` (loopback)

View logs with `mise run broker:logs` (or
`podman logs -f mosquitto-tls` / `docker logs -f mosquitto-tls`).

## Stopping the Broker

```bash
mise run broker:stop

# Or directly:
test/broker/stop-broker.sh
```

## Configuration

### Environment Variables

| Variable | Description | Default |
|----------|-------------|---------|
| `CONTAINER_RUNTIME` | Container runtime (`podman` or `docker`) | Auto-detected |
| `BROKER_HOST_IP` | Override the bind IP address | `127.0.0.1` (macOS), detected from `BROKER_INTERFACE` (Linux) |
| `BROKER_INTERFACE` | Override the Linux network interface | `eno1` |

Set these before running `mise run broker:start` to customize
the broker binding:

```bash
# Example: use Docker and bind to a different IP on Linux
CONTAINER_RUNTIME=docker BROKER_HOST_IP=10.0.0.1 \
  BROKER_INTERFACE=eth0 mise run broker:start
```

### Ports

- **1883**: MQTT (non-encrypted)
- **8883**: MQTTS (TLS encrypted)

### TLS Settings

- **ECDSA** self-signed certificates generated by
  `mise run tls:server:broker`
- CN (Common Name) set to match the bind IP (platform-detected
  or overridden via `BROKER_HOST_IP`)
- Supports TLS 1.2 and TLS 1.3
- Uses ECDSA P-256 (prime256v1) curve for keys
- Compatible with embedded-tls cipher suite:
  TLS_AES_128_GCM_SHA256

### Cipher Suites

The broker supports TLS 1.3 cipher suites including:

- `TLS_AES_128_GCM_SHA256` ✓ **Compatible with embedded-tls**
- `TLS_AES_256_GCM_SHA384`
- `TLS_CHACHA20_POLY1305_SHA256`

TLS 1.2 fallback ciphers use ECDHE-ECDSA (matching the ECDSA
certificates).

> **Note:** embedded-tls requires ECDSA certificates.  The
> TLS scripts (`gen-tls-cert.sh`) generate ECDSA (not RSA)
> certificates, which are bind-mounted into the container.

## Manual Container Commands

The examples below use `podman`; substitute `docker` if that
is your runtime.

> **Note:** Podman prefixes local images with `localhost/`.
> When using Docker, omit the `localhost/` prefix (e.g.,
> `mosquitto-tls:latest` instead of
> `localhost/mosquitto-tls:latest`).

### Build

```bash
podman build -t localhost/mosquitto-tls:latest test/broker/
# Docker equivalent:
docker build -t mosquitto-tls:latest test/broker/
```

### Run (Linux)

```bash
podman run -d \
    --name mosquitto-tls \
    -p 192.168.1.1:1883:1883 \
    -p 192.168.1.1:8883:8883 \
    -v mosquitto-data:/mosquitto/data \
    -v mosquitto-log:/mosquitto/log \
    -v .local/certs/ca/root.crt:/mosquitto/certs/root.crt:ro,Z \
    -v .local/certs/server/broker.crt:/mosquitto/certs/broker.crt:ro,Z \
    -v .local/private/broker.key:/mosquitto/certs/broker.key:ro,Z \
    localhost/mosquitto-tls:latest
```

> **Note:** The `:Z` SELinux suffix is only needed on Fedora,
> RHEL, and other SELinux-enabled distros.  Omit it on Debian,
> Ubuntu, Arch, and macOS.

### Run (macOS)

```bash
podman run -d \
    --name mosquitto-tls \
    -p 127.0.0.1:1883:1883 \
    -p 127.0.0.1:8883:8883 \
    -v mosquitto-data:/mosquitto/data \
    -v mosquitto-log:/mosquitto/log \
    -v .local/certs/ca/root.crt:/mosquitto/certs/root.crt:ro \
    -v .local/certs/server/broker.crt:/mosquitto/certs/broker.crt:ro \
    -v .local/private/broker.key:/mosquitto/certs/broker.key:ro \
    localhost/mosquitto-tls:latest
```

### View Logs

```bash
podman logs -f mosquitto-tls

# Or:
mise run broker:logs
```

### Stop and Remove

```bash
podman stop mosquitto-tls
podman rm mosquitto-tls

# Or:
mise run broker:stop
```

## Testing the TLS Connection

### Using mosquitto_sub (MQTT client)

```bash
# Subscribe to a topic over TLS (adjust IP for your platform)
mosquitto_sub -h 127.0.0.1 -p 8883 \
    --cafile .local/certs/ca/root.crt -t test/topic
```

### Using openssl

```bash
# Test TLS handshake (adjust IP for your platform)
openssl s_client -connect 127.0.0.1:8883 \
    -CAfile .local/certs/ca/root.crt

# Test with specific TLS version
openssl s_client -connect 127.0.0.1:8883 -tls1_3
```

### Check supported ciphers with nmap

```bash
nmap --script ssl-enum-ciphers -p 8883 127.0.0.1
```

## Troubleshooting

### Interface not found (Linux)

If the default interface `eno1` doesn't exist, set the
`BROKER_INTERFACE` environment variable:

```bash
BROKER_INTERFACE=eth0 mise run broker:start
```

View available interfaces:

```bash
ip -br addr
```

### Container runtime not reachable (macOS)

Start your container VM backend before launching the broker:

**Podman users:**

```bash
podman machine start
# Or, if using Lima:
limactl start podman
```

**Docker users:**

```bash
# Docker Desktop:
open -a Docker

# Colima:
colima start
```

### Certificate SAN mismatch

If the broker cert was generated with a different IP than the
current bind address, the start script will detect the mismatch
and print instructions.  To regenerate just the broker cert:

```bash
mise run tls:server:broker -- --force
mise run broker:start
```

If that doesn't resolve it, delete all certs and retry:

```bash
rm -rf .local/certs .local/private .cache/signing_requests
mise run tls:server:broker
mise run broker:start
```

### Certificate issues

Certificates are generated once and cached in `.local/`.  To
force regeneration:

```bash
mise run tls:server:broker -- --force
```

## Notes

- The broker allows anonymous connections for testing
- Self-signed certificates will trigger warnings in production
  clients
- For production use, replace with proper CA-signed certificates
- The container automatically restarts unless explicitly stopped
